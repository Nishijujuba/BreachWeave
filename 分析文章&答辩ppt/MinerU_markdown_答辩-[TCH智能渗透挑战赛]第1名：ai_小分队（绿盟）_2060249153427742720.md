智能决策要有工程边界：让 LLM 负责规划、判断和调度，但所有动作都必须通过受控工具、资源上限和生命周期约束落地。

执行环境必须隔离可重置：渗透测试 Agent 会运行脚本、安装工具、接触恶意服务，必须用容器隔离执行，避免污染宿主环境。

- 经验要沉淀成共享状态：不要让每个 Agent 从零开始，把失败边界、成功经验沉淀下来，形成可继承的团队经验。

架构要做“稳定骨架”，不要做“能力枷锁”：Agent的核心能力来自模型本身，系统架构只应提供必要的状态、工具、隔离和反馈闭环；不要用过度复杂的流程、越精简、稳定、可组合的框架，越能随着模型能力提升而自然进化。

# Observer Harness: Efficiency Reminder

第二届智能渗透挑战赛·决赛

铸刃止戈 以智御危

![image](https://cdn-mineru.openxlab.org.cn/result/2026-05-29/d582a474-7a67-4a10-b9ab-ad163954603c/b0ba7ba8d77d157e5aeaf35e9e17a672100a0c69f4df53c2b2f421473b9ebd41.jpg)


痛点：Agent长任务中容易被近期上下文和工具反馈牵引，执行策略会逐步发生偏移

引入 Observer Agent，基于任务目标持续审查最近几轮执行表现和工具调用反馈，不干预 Agent 推进任务,而是判断当前推进是否仍然有效，在适当的时机做打断

![image](https://cdn-mineru.openxlab.org.cn/result/2026-05-29/d582a474-7a67-4a10-b9ab-ad163954603c/4162c72c16b93e25a8d72cddf595ee2a686dd7d5f8a864b52ecbe0682431f968.jpg)


长任务推进到后期，真正先失真的往往不是能力，而是状态本身：假设、证据、失败边界和过程日志逐渐混在一起

将状态拆成两层：Idea 维护当前值得推进的攻击方向，Memory 保留可跨轮复用的事实、证据与约束 Observer 持续整理、更新和压缩这两块状态板，让 Solver 始终面向低噪音、可决策的上下文推进任务

![image](https://cdn-mineru.openxlab.org.cn/result/2026-05-29/d582a474-7a67-4a10-b9ab-ad163954603c/47da590f28ae71f8f8a6cb42679b6b407192350f9f064d80b938d8a531932c0f.jpg)


长任务执行中，Agent 可能因误判、停顿或上下文退化而过早结束任务

我们将“任务是否结束”的判断从模型主观决策中抽离，改由系统基于任务状态统一约束结束条件由任务状态决定，而不是由模型当下的主观判断决定。

![image](https://cdn-mineru.openxlab.org.cn/result/2026-05-29/d582a474-7a67-4a10-b9ab-ad163954603c/fc36d89caec44ac2abb0eb0069d2b68187689a344cb34372c1432b67f26af8bf.jpg)
